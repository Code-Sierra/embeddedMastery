Execution models, layering, driver and HAL design, state machines, patterns, memory and error policy, testability, model-based design and product lines. Running example: a battery-swap-station slot controller (charger slot with door sensor, button, CAN link to the battery BMS, contactor and overcurrent comparator). // 32 — EXECUTION-MODEL SIMULATOR

Same Device, Four Architectures

A charger-slot controller runs a 1 ms control step every 10 ms and a display refresh + log write every 100 ms (the flash write is the slow part: in a blocking design the CPU busy-waits on the SPI flash's BUSY bit). Inject event bursts, pick an architecture and watch latency, lost events, CPU load and control jitter change. The model runs a 300 ms window in 10 µs ticks on one CPU: interrupts preempt everything, each ISR costs 1 tick, an RTOS context switch costs 1 tick (real FreeRTOS on a 168 MHz M4 is about 1–2 µs, so the model is pessimistic), SysTick fires every 1 ms. The CAN peripheral has a 3-frame hardware RX FIFO (true of bxCAN on the F4 and FDCAN on the G0).

RULES THE STEPPER IMPLEMENTS

        

          
RULEWHAT HAPPENS

          
          
Run-to-completionOne event is processed completely (all exits, actions, entries, initial transitions) before the next is taken from the queue. No re-entrancy, so no locks inside the machine.

          
Event bubblingThe active leaf state gets the event first. If it has no transition for it, or every guard is false, the parent is tried, up to the top. If nobody handles it, the event is discarded (UML default). This is what makes hierarchy "programming by difference".

          
LCAFor an external transition from source S to target T, the least common ancestor is the deepest state that is a proper ancestor of both. Exits run from the current leaf up to (not including) the LCA; entries run from just below the LCA down to T.

          
Self-transitionRESTART on CHARGING targets CHARGING itself: external semantics exit CC, exit CHARGING, then re-enter CHARGING and take its initial transition to CC.

          
Internal transitionTICK in CHARGING runs update_soc() with no exit or entry: the configuration does not change.

          
Initial transitionEntering a composite state that is not the final target follows its initial transition (and, for OPERATIONAL, a choice on battery_present) until a leaf is reached.

          
Shallow history (H)When CHARGING is exited, the direct substate that was active (CC or CV) is recorded. DOOR_CLOSE from PAUSED targets H: it resumes CC or CV instead of restarting at CC.

          
Entry/exit orderEntries are outer → inner; exits are inner → outer. Code generated by Stateflow and QP both follow this; a hand-written flat switch often gets it wrong.

HOW THE CHECKER DECIDES (and how to explain it)

        
    
          
  1. Every edge A → B means "A includes B's header or calls B's functions". Layers are numbered from 0 (Application) to 6 (CMSIS/device).
    2. 
          
  2. Downward (layer(B) > layer(A)): allowed. This is the normal direction: the app uses services, services use drivers, drivers use the HAL.
    3. 
          
  3. Same layer: allowed, but such edges are where cycles hide, so they are checked by the cycle search.
    4. 
          
  4. Upward (layer(B) < layer(A)): violation. Example: can_drv → app_slot_fsm. The driver can no longer be compiled, tested or reused without the application.
    5. 
          
  5. Vendor leak: anything above the HAL including stm32g0xx.h. Example: the control loop writing TIM1->CCR1. Porting to another MCU now means editing product logic.
    6. 
          
  6. Layer skip ≥ 3 layers (not to the device header): warning only. app_ui → hal_gpio reads an LED pin through the HAL; legal, but usually a small LED driver should own that pin.
    7. 
          
  7. Cycle: a depth-first search over all edges; reaching a module already on the current search path means a loop such as app_slot_fsm → can_proto → can_drv → app_slot_fsm.
    8. 
        

        
I enforce layering mechanically: each dependency must point to the same or a lower layer, no vendor header above the HAL, and no cycles, which a DFS over the include graph finds. Upward notifications become callbacks registered by the upper layer or events on a bus that sits below both.
