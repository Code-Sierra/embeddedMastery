From a Line of C to a Voltage on Copper

Read this tab from top to bottom before anything else. It builds the topic from zero: what problem the hardware–software interface is, what is physically on the board, every key word defined one at a time, and then one complete worked example with real numbers — a button that switches a 12 V relay, lights an LED and prints a log line on an STM32F407. Every later tab (Concepts, Lab, Calculators, Registers, Scenarios) zooms into one part of this picture.

1What problem does this topic solve?

When you write firmware, everything you do eventually becomes a number written to an address. For example, GPIOA->BSRR = 1U << 5; writes the number 0x0000_0020 to address 0x4002_0018. Inside the microcontroller (MCU), that address is not memory: it is a register wired to a little circuit that drives pin PA5. A moment later, PA5 changes from 0 V to about 3.3 V, current flows through a resistor and an LED lights.

The "hardware–software interface" is everything between that C statement and the result in the real world. It has two halves:

  1. The software half — how registers are laid out, which bits mean what, how to write them safely (some bits clear when you write 1, some when you write 0, some when you merely read them), and how drivers wrap this up so the application never sees raw addresses.
  2. The hardware half — what the pin can physically do (how many milliamps, which voltages), what is connected to it on the board (resistors, transistors, other chips), how the board is powered, clocked and reset, and what goes wrong electrically (shorts, noise, slow edges, voltage spikes).

Firmware engineers are interviewed on both halves because in real life bugs cross the line all the time. A "software" bug where the UART prints garbage is often a wrong crystal capacitor. A "hardware" bug where a button press is lost is often a single wrong |= in an interrupt handler. Bring-up — the first power-on of a brand-new board — is where both halves meet, and it is the most common interview story of all.

Reference part for this page: STM32F407VG (ARM Cortex-M4 core, 3.3 V supply, up to 168 MHz). Numbers come from its datasheet DS8626 and reference manual RM0090. Other vendors (NXP, TI, Microchip) use different names but the same ideas.

2The physical picture: what is on a typical board?

Below is the board we will use for the worked example. Read it left to right: power comes in, is converted to the voltages the chips need, the MCU sits in the middle, and the MCU's pins reach out to things in the world.

Five things exist on every MCU board, and you will meet each of them in the Concepts tab:

  1. Power: an input (here 12 V), protection, and regulators that make the exact voltages the chips need (here 5 V and 3.3 V), plus small capacitors next to every chip.
  2. Clock: a crystal (here 8 MHz) or the MCU's internal oscillator. Every timer, baud rate and delay is derived from it, so a wrong clock shows up as "the UART prints garbage".
  3. Reset and boot: the NRST pin that restarts the chip and the BOOT0 pin that chooses where it starts executing. If these are wrong, nothing runs.
  4. Debug access: the SWD header the programmer/debugger plugs into, and usually a UART for log messages.
  5. The application's I/O: buttons, LEDs, transistors switching loads, sensors on buses. Each needs the right electrical "glue" (resistors, diodes, translators) between pin and world.

3Key terms, defined one by one

Do not skip this. Every word below is used later without explanation. Read each definition and the example next to it.

// DOCUMENTS

Datasheet
The document that says what one specific chip guarantees: its pins, voltage and current limits, timing, and package. For the STM32F407 it is DS8626. Example: "each pin may carry at most 25 mA".
Reference manual (RM)
The document that explains how to program the chip: every peripheral and every register bit. Shared by a whole family. For the F407 it is RM0090.
Errata sheet
The list of known silicon bugs for each chip revision, with workarounds (ES0182 for the F407). Example: "the first write after enabling a peripheral clock can be lost".
Schematic
The circuit drawing of the board: which pin connects to which resistor, chip or connector. Your map of the hardware.

// REGISTERS AND SOFTWARE

Peripheral
A hardware block inside the MCU that does one job: GPIO (pins), USART (serial port), I²C, timers, ADC (analog-to-digital converter).
Register
A 32-bit location inside a peripheral that controls it or reports its status. Writing it changes hardware behaviour; reading it tells you hardware state.
Memory-mapped I/O
Registers have ordinary addresses, so the CPU reads and writes them with the same load/store instructions it uses for RAM. GPIOA starts at 0x4002_0000.
Bit field
A group of bits inside a register with one meaning. Example: GPIOA_MODER bits 11:10 (two bits) set the mode of pin PA5.
volatile
A C keyword that tells the compiler "every read and write of this really happens, in order — do not cache or remove it". Every register is accessed through a volatile pointer.
Read-modify-write (RMW)
REG |= BIT; is really three steps: read the register, change a bit, write the whole register back. Safe on ordinary registers, dangerous on flag registers.
W1C (rc_w1)
"Write 1 to clear": a status bit that hardware sets and that you clear by writing 1 to it. Writing 0 does nothing. EXTI_PR works this way.
CMSIS / HAL / LL
CMSIS = ARM's standard C headers that describe registers as structs. HAL and LL = ST's driver libraries (HAL is high-level and large; LL is a thin layer over the registers).
Driver / BSP
A driver is the code that operates one peripheral or device. The BSP (board support package) is the one place that knows this board: which pin has the LED, whether it is active-low.

// PINS AND ELECTRICAL

GPIO
General-purpose input/output pin. As an output it drives 0 V or 3.3 V; as an input it reports whether the voltage is low or high.
VOH / VOL
Output high / output low voltage the pin guarantees at a given current. F407: VOH ≥ 2.9 V and VOL ≤ 0.4 V while carrying 8 mA.
VIH / VIL
Input high / input low thresholds: above VIH is read as 1, below VIL as 0, in between is undefined. At 3.3 V: VIH ≈ 1.8 V, VIL ≈ 1.0 V.
Source / sink
A pin sources current when it drives high and current flows out of it; it sinks current when it drives low and current flows into it.
Push-pull
An output that actively drives both high and low (two transistors).
Open-drain
An output that can only pull low or let go. A resistor (the pull-up) makes the high level. Used for I²C and shared lines.
Pull-up / pull-down
A resistor from a signal to the supply (up) or to ground (down) that sets the signal's level when nothing is driving it.
Floating / hi-Z
A pin or wire that nothing drives. Its voltage wanders with leakage and noise. After reset, STM32 GPIOs are inputs, i.e. floating unless pulled.
Rail
A supply voltage net on the board: 3V3, 5V, GND.
LDO / buck
Two kinds of voltage regulator. An LDO (low-dropout linear regulator) burns the voltage difference as heat. A buck (switching step-down converter) uses an inductor and switches, wasting only ~10 %.
Decoupling capacitor
A small capacitor (typically 100 nF) right next to each chip supply pin that supplies the chip's fast current spikes.
MOSFET, VGS(th), RDS(on)
A transistor used as a switch. VGS(th) is the gate voltage where it starts to conduct; RDS(on) is its resistance when fully on, valid only at the gate voltage the datasheet states.
Flyback diode
A diode across a coil (relay, motor) that gives the coil's current somewhere to go when the switch opens, preventing a large voltage spike.
Level shifter
A circuit or chip that connects signals between two voltage domains, e.g. a 1.8 V sensor and a 3.3 V MCU.

// CLOCK, RESET, DEBUG, BRING-UP

HSI / HSE / PLL
HSI = the MCU's internal 16 MHz RC oscillator (±1 %). HSE = the external crystal oscillator (here 8 MHz, ±0.003 %). PLL = a circuit that multiplies a clock up, e.g. 8 MHz → 168 MHz.
Load capacitors
The two small capacitors (e.g. 15 pF) from each crystal pin to ground. Their value must match the crystal, or it runs off-frequency or does not start.
NRST, POR, BOR
NRST is the reset pin (low = reset). POR = power-on reset. BOR = brown-out reset, which holds the chip in reset when the supply sags below a set level.
Supervisor
A small chip that holds NRST low until the supply has been good for ~200 ms.
BOOT0 / strap pin
A pin read once at reset to choose a mode. BOOT0 = 0 runs your program from flash; 1 runs ST's built-in bootloader.
SWD
Serial Wire Debug: the 2-wire debug interface (SWDIO, SWCLK) a programmer such as ST-LINK uses to flash and debug the MCU.
Bring-up
The structured first power-on and test of a new board: inspect, measure, power carefully, prove each block.
Current-limited supply
A bench power supply set to stop at a maximum current (e.g. 100 mA), so a short circuit cannot burn the board.
Test point (TP)
A pad on the board meant for a probe, e.g. "TP3 3V3".

4One register write, followed all the way to the copper

Take this single line, which turns on an LED on PA5:

GPIOA->BSRR = (1U << 5);      // set PA5 high
  1. The C compiler sees GPIOA, which the CMSIS header defines as ((GPIO_TypeDef *)0x40020000). BSRR is the member at offset 0x18 in that struct, so the address is 0x4002_0000 + 0x18 = 0x4002_0018. Because the member is volatile, the compiler must emit the store.
  2. The CPU executes a store instruction (STR) that puts the value 0x0000_0020 (bit 5 set) on the internal bus with address 0x4002_0018.
  3. The bus matrix decodes the address: 0x4002_xxxx belongs to the AHB1 bus, and 0x4002_0000–0x4002_03FF is the GPIOA block. The write is delivered there. (If the GPIOA clock were not enabled in RCC_AHB1ENR, the block would ignore the write — the most common "my code does nothing" bug.)
  4. The GPIOA block interprets BSRR specially: a 1 in bits 0–15 sets that pin's bit in ODR (output data register); a 1 in bits 16–31 resets it. Zeros do nothing. So only PA5 changes — no other pin is touched, which is why BSRR is "atomic".
  5. The output driver for PA5 (if MODER says "output") switches on its upper transistor, connecting the pin to 3.3 V through roughly 40–50 Ω of internal resistance.
  6. On the board, current flows 3.3 V → pin → 220 Ω → LED → GND. The LED drops about 2.0 V, so I ≈ (3.3 − 2.0) / (220 + 40) ≈ 5 mA, and it lights.

Every interview question in this topic is about one of those six arrows: the address and struct (step 1), access rules like W1C (step 4), the pin's electrical limits (step 5), or the circuit on the board (step 6).

5Worked example: button → relay + LED + UART log

Requirement: when the user presses button S1, toggle a 12 V relay K1 (it switches a pump), mirror the relay state on LED D2, and print "relay=ON" or "relay=OFF" to a PC terminal at 115200 baud. Input power is a 12 V adapter. We will design each piece with real numbers, then write the register code.

// STEP 1 — POWER: WHICH REGULATOR?

The MCU, LED and UART need 3.3 V at about 60 mA (MCU running at 168 MHz ≈ 40–50 mA plus LED and margin). The relay coil runs directly from 12 V.

  1. Option A: one LDO from 12 V to 3.3 V. Heat = (Vin − Vout) × I = (12 − 3.3) × 0.060 = 0.52 W. In a SOT-223 package with θJA ≈ 90 °C/W (θJA = how many °C the chip heats per watt), that is 0.52 × 90 = +47 °C over ambient. Survivable, but hot, and efficiency is only 3.3/12 = 27 %.
  2. Option B (chosen): a buck from 12 V to 5 V, then an LDO 5 → 3.3 V. LDO heat = (5 − 3.3) × 0.060 = 0.10 W → only +9 °C. The buck wastes ≈ 10 % of what it delivers. The LDO also filters the buck's switching ripple, giving the MCU a quiet rail.
  3. Each MCU VDD pin gets a 100 nF capacitor right at the pin, plus one 4.7 µF bulk capacitor; the F407's two VCAP pins get 2.2 µF each (they stabilise its internal 1.2 V core regulator).

// STEP 2 — PICK THE PINS FROM THE DATASHEET

// STEP 3 — THE BUTTON CIRCUIT

  1. The button connects PA0 to GND when pressed. When released, something must hold PA0 high, otherwise it floats. We use the MCU's internal pull-up (≈ 40 kΩ, set in GPIOA_PUPDR).
  2. Current while pressed = 3.3 V / 40 kΩ = 82 µA. Small enough even for a battery product.
  3. Logic: released = 1, pressed = 0 (active-low). A mechanical button bounces for 1–10 ms, so firmware accepts a press only after the input has been stable for 20 ms (debounce).

// STEP 4 — THE LED

Red LED, forward voltage VF ≈ 2.0 V. Target 5 mA (well inside the pin's 8 mA rating). The pin's own resistance is about 40 Ω.

R = (V_DD − V_F) / I − R_pin = (3.3 − 2.0) / 0.005 − 40 = 260 − 40 = 220 Ω
Check: I = 1.3 V / (220 + 40) Ω = 5.0 mA   ✔   P_R = I²·R = 0.005² × 220 = 5.5 mW

// STEP 5 — THE RELAY: WHY A TRANSISTOR AND A DIODE

  1. Coil current = 12 V / 120 Ω = 100 mA. A GPIO is rated 25 mA absolute maximum and only 3.3 V — it cannot drive the coil directly. So a transistor switches the coil's ground side ("low-side switch").
  2. We use an NPN transistor (BC817). To be fully on ("saturated") it needs base current IB ≈ IC / 20 = 100 mA / 20 = 5 mA. The base–emitter junction drops 0.7 V, so RB = (3.3 − 0.7) / 5 mA = 520 Ω → nearest standard value 510 Ω.
  3. A 10 kΩ resistor from base to emitter keeps the transistor off while PB0 floats during reset (the pin is an input for the first milliseconds after power-up).
  4. The coil is an inductor (≈ 80 mH). When the transistor turns off, the coil "wants" to keep its 100 mA flowing. With nowhere to go, the collector voltage jumps to tens of volts (V = L·di/dt: 80 mH × 100 mA / 1 µs = 8000 V in theory — in practice the transistor breaks down first). The spike also couples into ground and resets MCUs. A flyback diode (1N4148) across the coil, cathode to +12 V, lets the current circulate and limits the collector to 12.7 V.

// STEP 6 — THE CLOCK AND THE BAUD RATE

  1. After reset the chip runs on HSI (16 MHz internal, ±1 %). UART needs better than about ±2 % total error, and USB/CAN need a crystal, so we enable the 8 MHz crystal (HSE).
  2. The PLL multiplies it: f = 8 MHz / M × N / P = 8 / 8 × 336 / 2 = 168 MHz system clock. APB2 (where USART1 lives) runs at 168 / 2 = 84 MHz.
  3. Baud rate divider (16× oversampling): USARTDIV = fAPB2 / (16 × baud) = 84 000 000 / (16 × 115 200) = 45.57. Mantissa = 45, fraction = 0.57 × 16 = 9.1 → 9. BRR = (45 << 4) | 9 = 0x2D9.
  4. Actual baud = 84 MHz / (16 × 45.5625) = 115 226 → error +0.02 %. ✔ If the code thinks the crystal is 25 MHz while it is really 8 MHz, every rate is off by 3× and the terminal shows garbage.

// STEP 7 — THE REGISTER CODE

/* 1. Turn on the clocks of the blocks we use */
RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN | RCC_AHB1ENR_GPIOBEN;
RCC->APB2ENR |= RCC_APB2ENR_USART1EN;
(void)RCC->APB2ENR;                         /* read-back: errata ES0182 delay */

/* 2. PA5 output, PA9/PA10 alternate function, PA0 input with pull-up */
GPIOA->MODER = (GPIOA->MODER & ~(GPIO_MODER_MODER0 | GPIO_MODER_MODER5 |
                                 GPIO_MODER_MODER9 | GPIO_MODER_MODER10))
             | (1U << 10) | (2U << 18) | (2U << 20);
GPIOA->PUPDR = (GPIOA->PUPDR & ~GPIO_PUPDR_PUPDR0) | (1U << 0);
GPIOA->AFR[1] = (GPIOA->AFR[1] & ~0xFF0U) | (7U << 4) | (7U << 8);

/* 3. PB0 output, driven low first so the relay never twitches */
GPIOB->BSRR  = GPIO_BSRR_BR0;
GPIOB->MODER = (GPIOB->MODER & ~GPIO_MODER_MODER0) | (1U << 0);

/* 4. USART1: 115200 8N1, TX + RX on, then enable */
USART1->BRR = 0x2D9;
USART1->CR1 = USART_CR1_TE | USART_CR1_RE;
USART1->CR1 |= USART_CR1_UE;

/* 5. Act on a debounced press */
static bool on;
on = !on;
GPIOB->BSRR = on ? GPIO_BSRR_BS0 : GPIO_BSRR_BR0;   /* relay  */
GPIOA->BSRR = on ? GPIO_BSRR_BS5 : GPIO_BSRR_BR5;   /* LED    */
uart_puts(on ? "relay=ON\r\n" : "relay=OFF\r\n");
CODEMEANING
RCC->AHB1ENR |= …GPIOAENPeripherals start with their clock switched off to save power. Until this bit is 1, writes to GPIOA are ignored and reads return 0.
(void)RCC->APB2ENR;A dummy read. The F4 errata says the clock takes a couple of cycles to arrive; reading the RCC register back stalls the CPU until it has.
GPIOA->MODER = (… & ~mask) | …Read-modify-write: clear only the 2-bit fields of PA0, PA5, PA9, PA10, then set new values. Bits for PA13/PA14 (debug) are preserved.
(1U << 10)PA5's field is bits 11:10 (pin × 2 = 10). Value 01 = general-purpose output.
(2U << 18) | (2U << 20)PA9 (bits 19:18) and PA10 (bits 21:20) = 10 = alternate function. PA0 (bits 1:0) left at 00 = input.
PUPDR … (1U << 0)PA0's pull field = 01 = pull-up. The button pulls the pin to 0 when pressed.
AFR[1] … (7U<<4)|(7U<<8)AFR[1] (AFRH) covers pins 8–15, 4 bits each. PA9 is bits 7:4, PA10 bits 11:8. AF7 = USART1.
GPIOB->BSRR = BR0 before MODERSet the output latch to 0 before making the pin an output, so the first driven level is "off".
USART1->BRR = 0x2D9Mantissa 45 (0x2D) in bits 15:4, fraction 9 in bits 3:0 → 115 200 baud from 84 MHz.
CR1 = TE | RE, then |= UEConfigure the transmitter and receiver, and set UE (USART enable) last, as RM0090 recommends.
BSRR = on ? BS0 : BR0BSRR sets (BSx, bits 0–15) or resets (BRx, bits 16–31) a single pin in one write — no read, so no race with interrupts touching other pins.

Final register values you could check in a debugger: GPIOA_MODER = 0xA800_0000 (reset) | 0x0000_0400 (PA5) | 0x0028_0000 (PA9/PA10) = 0xA828_0400. GPIOA_AFR[1] = 0x0000_0770. USART1_BRR = 0x0000_02D9.

// STEP 8 — WHAT HAPPENS WHEN THE BUTTON IS PRESSED (TIMELINE)

A firmware write is a store to a memory-mapped register; the peripheral turns it into a pin state, and the circuit on the board decides what that pin can safely do. For a 12 V relay I'd use a low-side NPN or logic-level FET with a base/gate resistor and pull-down, a flyback diode across the coil, the pin set low before it becomes an output, and atomic BSRR writes in firmware.

6Bringing that board up for the first time

The board comes back from assembly. Nothing has ever run on it. Here is the order, and why each step comes before the next. The Bring-Up Lab tab lets you practise this order on seven simulated boards.

  1. Look under a microscope: chips rotated correctly (pin-1 dot), diodes and LEDs the right way round, no solder bridges, no missing parts. Why first: it costs nothing and some faults (a reversed regulator) destroy parts the moment power arrives.
  2. Measure resistance from each rail to GND with the board unpowered. A healthy 3V3 rail reads a value that climbs (the meter is charging capacitors) to kilo-ohms. A steady 0.4 Ω means a short. Why before power: a short at full power burns the evidence.
  3. Power from a current-limited bench supply at 12 V, limit 100 mA. This board should draw ~10 mA with blank flash. If the supply hits the limit ("CC" mode), switch off and find the hot part.
  4. Measure each rail at its test point: 5.0 V, 3.30 V; ripple small (tens of mV).
  5. Check NRST is high (3.3 V) and BOOT0 is low (0 V). If NRST is low, the chip is held in reset and nothing else can work.
  6. Connect the debugger over SWD and read the chip's ID: DEV_ID 0x413 = STM32F405/407. Now you know the core is alive.
  7. Flash a tiny test program that enables the crystal and PLL, blinks the LED and prints over UART. LED blinking at 1 Hz proves code runs; readable UART text proves the clock tree is right.
  8. Test each function alone: press the button and watch PA0 on a scope; toggle the relay and look at the collector of Q1 — it should clamp at 12.7 V, not spike.

Why the order matters: each step proves the foundation the next one stands on. If you jump to "the UART doesn't work", you could spend a day in code when the real problem was a crystal that never started (step 7) or a reset pin held low (step 5).

First Power-On: Find the Fault

Seven freshly assembled boards came back from the contract manufacturer. Each is either good or has one fault. Work down the bring-up checklist, pick the measurement to take, read the instrument, then commit to a diagnosis. Your first diagnosis is scored. Taking steps out of order works, but the lab will tell you what a real bring-up engineer would have risked. Flash is blank until you program it in step 7.

// HOW TO USE THIS LAB

  1. Pick BOARD 1, then click the checklist buttons from step 1 downwards. Read the instrument panel: the big value is the reading, the text explains it, and the cyan "why this step" box says what that measurement proves.
  2. Try BOARD 2 and skip straight to "Bench PSU" without the resistance check — notice the warning in the notebook. This shows why you measure ohms before applying power.
  3. On any board, try "Scope: OSC_OUT" before "Program bring-up image" and notice the flat trace is expected: HSE is off until firmware enables it. Then program and measure again.
  4. On a board where the LED blinks only sometimes, compare "DMM: TP5 BOOT0" with the golden board's 0.00 V — a drifting voltage means a floating strap pin.
  5. Commit a diagnosis only when two independent measurements agree. Then read KEY EVIDENCE / FIX / LESSON, and press "reset this board" to try a shorter path.

60-SECOND REVISION

          
    
            
  • Datasheet = what the chip guarantees; reference manual = how to program it; errata = where it lies.
    • 
            
  • Absolute max is a damage limit, not an operating point. Design to recommended operating conditions.
    • 
            
  • Open-drain + pull-up gives wired-AND and level translation; rise time = R·C, fall time = strong driver.
    • 
            
  • Pull-up value is a trade: small R = fast edges + more current; large R = slow edges + noise sensitivity.
    • 
            
  • N-FET low side: gate resistor 22–100 Ω, gate pull-down 100 kΩ, RDS(on) specified at ≤ your VGS.
    • 
            
  • Every inductor needs a current path when switched off: flyback diode, TVS, or diode+Zener for fast release.
    • 
            
  • FT pins take 5 V only while powered and not in analog mode; injection current flows through clamp diodes.
    • 
            
  • LDO efficiency ≈ Vout/Vin. Heat = ΔV·I. Check TJ with θJA.
    • 
            
  • 100 nF per supply pin, as close as possible, via straight to the plane; plus bulk. MLCCs lose capacitance with DC bias.
    • 
            
  • Crystal: C1 = C2 = 2(CL − Cstray). Gain margin ≥ 5. Cold raises ESR.
    • 
            
  • NRST on STM32 is bidirectional open-drain with a ~40 kΩ pull-up: supervisors must be open-drain.
    • 
            
  • A trace is a transmission line when its delay exceeds about 1/6 of the edge rise time. Edge speed matters, not clock frequency.
    • 
            
  • CMSIS: volatile struct overlay, _Pos/_Msk macros, reserved padding, verify offsets.
    • 
            
  • W1C: clear with a plain write of the flag. rc_w0: write the inverse. Never RMW either.
    • 
            
  • Bring-up: look → Ω → current-limited power → rails → reset/boot → SWD → blink → UART → peripherals.
    • 
            
  • Isolate HW vs SW: known-good firmware on suspect board, suspect firmware on known-good board, scope the pin vs read the register.
