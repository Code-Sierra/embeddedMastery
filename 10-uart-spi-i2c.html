Serial Buses From Zero

A guided tutorial, read top to bottom (about 30 minutes). It builds UART, SPI and I²C from the problem they solve, through the wires and the vocabulary, to three complete worked examples with real numbers on an STM32F407. Mark each section when it makes sense; then go deeper on the Concepts tab.

01The problem: chips on a board need to swap bytes

Picture a typical embedded board: an STM32F407 microcontroller (MCU = microcontroller unit, a CPU with its own memory and peripherals on one chip) sits in the middle. Around it are a GPS module that reports position as text, an external flash chip that stores logs, a temperature sensor, and an EEPROM that holds calibration data. None of these chips share memory with the MCU. The only way to get a byte from the sensor into a variable in your C program is to send it, bit by bit, over copper wires between the chips.

The most obvious way would be parallel: 8 data wires, one per bit, plus a strobe wire that says "the 8 wires are valid now". That is fast, but it costs 9+ pins per device. An STM32F407 in a 64-pin package has only about 50 usable I/O pins, and every pin also costs PCB routing space. So almost all chip-to-chip links on a board are serial: the bits of a byte travel one after another over a single data wire, and some agreement tells the receiver when to look at the wire.

One MCU, three different serial buses. UART: 2 wires, one partner. SPI: 4 wires, fast. I²C: 2 shared wires for many chips.

Every serial link has to answer two questions, and the three buses on this page are simply three different answers:

  1. When should the receiver read the wire? A bit is just a voltage that lasts for a while. The receiver needs to know where one bit ends and the next begins. This is the timing or clocking question.
  2. Who is talking, and to whom? If several chips share wires, they must take turns, and the sender must say which chip it means. This is the direction and addressing question.

[[say]] Serial buses exist to save pins: bits travel one after another on one wire. Every serial bus must solve timing (when to read) and addressing (who is talking). UART solves timing by agreeing on a baud rate and using a start bit, SPI and I²C by sending a clock wire; SPI addresses with chip-select wires, I²C with an address byte on the bus.

02The physical picture: a bit is a voltage held for a time

On a 3.3 V STM32F407, a pin driven to about 0 V means logic 0 and a pin driven to about 3.3 V means logic 1. The receiving pin does not see "0" or "1"; it sees a voltage, and it decides with thresholds. For 3.3 V CMOS logic the input reads 0 below about 0.3 × VDD ≈ 1.0 V and reads 1 above about 0.7 × VDD ≈ 2.3 V. Between those values the answer is undefined, which is why slow edges and noise matter.

A single bit is therefore "a voltage held for a certain time". If the sender holds the wire low for 8.68 µs, then high for 8.68 µs, it has sent "0, 1" at 115 200 bits per second. The receiver must look at the wire somewhere in the middle of each 8.68 µs window, because near the edges the voltage is still changing.

There are two ways a pin can drive a wire, and the difference explains most of this page:

  • Push-pull output: the pin has two transistors, one to VDD and one to GND. It actively drives both 1 and 0, so edges are fast (a few ns). UART and SPI use push-pull. The danger: if two push-pull outputs drive the same wire to opposite values, they short VDD to GND through the pins. So a push-pull wire must have exactly one driver at a time.
  • Open-drain output: the pin has only the transistor to GND. It can pull the wire to 0 or let go ("release"). A pull-up resistor (for example 2.2 kΩ to 3.3 V) pulls the wire to 1 when nobody pulls it down. Many chips can share one open-drain wire safely: if any one pulls low, the wire is low, and nothing gets damaged. I²C uses open-drain. The price: the rising edge is slow, because only the resistor charges the wire's capacitance.
Open-drain "wired-AND": the wire is 1 only if every chip lets go. One closed switch makes it 0. This one trick gives I²C its ACK, clock stretching and arbitration.
SAY IT LIKE THISA bit on a wire is a voltage held for one bit time, and the receiver must sample it in the middle. Push-pull outputs drive both levels and are fast but only one may drive a wire; open-drain outputs only pull low and rely on a pull-up resistor, so many chips can share the wire safely but rising edges are slow. UART and SPI are push-pull; I²C is open-drain.

03Key terms, defined one by one

Read these once now and come back whenever a word on another tab is unclear. Each one is used constantly in interviews.

Bit / byte
A bit is one binary digit, 0 or 1. A byte is 8 bits, for example 0x48 = 0100 1000 in binary = 72 decimal.
LSB / MSB
Least-significant bit (bit 0, worth 1) and most-significant bit (bit 7 of a byte, worth 128). UART sends LSB first; SPI and I²C normally send MSB first.
Baud rate
Symbols per second on the wire. For these buses one symbol = one bit, so 115 200 baud = 115 200 bits per second.
Bit time
How long one bit lasts: Tbit = 1 / baud. At 115 200 baud: 1 / 115 200 = 8.68 µs.
Frame
One complete package on the wire. A UART frame = start bit + data bits + optional parity + stop bit(s), e.g. 10 bits for one byte at 8N1.
Idle
The level of the line when nothing is being sent. UART idles high (1). I²C idles high because of the pull-ups. An SPI clock idles at the level set by CPOL.
TX / RX
Transmit and receive. The TX pin of one chip connects to the RX pin of the other: the wires cross.
Synchronous vs asynchronous
Synchronous: a clock wire travels with the data (SPI, I²C). Asynchronous: no clock wire; both sides use their own clock at an agreed rate (UART).
Full / half duplex
Full duplex: both directions at the same time (UART, SPI). Half duplex: one direction at a time on shared wires (I²C, 2-wire RS-485).
Master / slave (controller / target)
The master starts every transfer and drives the clock; the slave answers. The 2021 I²C spec renamed them controller and target; SPI documents often say main/subnode or controller/peripheral.
Shift register
A row of flip-flops (1-bit memories). On each clock edge every bit moves one place along. It converts a byte into a stream of bits (transmit) and back (receive).
Clock edge
The moment a clock changes level: rising edge = 0→1, falling edge = 1→0. Hardware acts on edges, not on levels.
Sample / latch
To read the line's value at one instant and store it. The receiver samples; the transmitter "shifts" or "launches" the next bit on the other edge.
Pull-up resistor (Rp)
A resistor from a line to VDD. It makes the line read 1 when no chip pulls it low. Its value trades speed (smaller = faster rise) against current (smaller = more current when low).
ACK / NACK
Acknowledge / not-acknowledge. In I²C, after each byte the receiver pulls SDA low for one clock (ACK = "got it") or leaves it high (NACK = "no" or "stop").
CS (chip select), also NSS / SS
An active-low SPI wire, one per slave. Pulling it low (0) tells that slave "this transfer is for you". "Active-low" means the active state is 0.
Parity
An extra bit chosen so the count of 1s is even (even parity) or odd (odd parity). It catches any single flipped bit, but not two.
Oversampling
The UART receiver checks the line 16 times per bit (×16) so it can find the start edge precisely and read each bit at its centre.
Peripheral registers (DR, SR, CR1…)
Memory-mapped addresses inside the MCU that control a hardware block. On STM32F4: DR = data register (write a byte to send, read a byte received), SR = status register (flags like TXE, RXNE), CR1/CR2/CR3 = control registers, BRR = baud rate register.
Flag (TXE, RXNE, TC, BSY…)
A status bit set by hardware. TXE = transmit data register empty, RXNE = receive data register not empty, TC = transmission complete, BSY = SPI busy.
Interrupt / ISR
A hardware signal that pauses the main program and runs an interrupt service routine (ISR), a C function such as USART2_IRQHandler, when a flag is set.
DMA
Direct memory access: a hardware engine that copies bytes between a peripheral's data register and RAM without the CPU touching each byte.
RS-232 / RS-485
Electrical standards that carry the same UART frames over longer cables. RS-232: inverted, ±3…15 V, one partner. RS-485: two wires carrying the difference (A−B), up to 1200 m and 32+ nodes.
APB1 / APB2, fPCLK
The two peripheral buses on STM32F4 and their clocks. At 168 MHz system clock: APB1 = 42 MHz (USART2/3, I2C, SPI2/3), APB2 = 84 MHz (USART1/6, SPI1). Baud and SPI-clock dividers start from these.
SAY IT LIKE THISI always define the vocabulary first: baud and bit time for timing, synchronous versus asynchronous for how the receiver finds the bits, push-pull versus open-drain for how the line is driven, and the status flags (TXE, RXNE, TC, BSY) that firmware actually waits on.

04Worked example A — UART sends the letter 'H'

Goal: the STM32F407 sends the character 'H' to a PC terminal through a USB-to-UART adapter, at 115 200 baud, 8N1. "8N1" means 8 data bits, No parity, 1 stop bit. We use USART2, whose clock is APB1 = 42 MHz.

Step 1. Work out the timing
  • Bit time: Tbit = 1 / 115 200 = 8.68 µs.
  • One frame at 8N1 = 1 start + 8 data + 1 stop = 10 bits = 10 × 8.68 = 86.8 µs.
  • Maximum useful throughput = 115 200 / 10 = 11 520 bytes per second, not 14 400 (115 200 / 8), because the start and stop bits also cost time.
Step 2. Program the baud-rate divider

The USART must produce one bit every 8.68 µs from its 42 MHz clock. The STM32F4 formula with 16× oversampling (OVER8 = 0) is USARTDIV = fCK / (16 × baud), and the BRR register holds USARTDIV × 16, so simply BRR = round(fCK / baud).

  1. 42 000 000 / 115 200 = 364.58.
  2. Round to the nearest integer: 365 = 0x16D.
  3. BRR[15:4] (the "mantissa", the integer part of USARTDIV) = 0x16 = 22, BRR[3:0] (the fraction, in 1/16ths) = 0xD = 13. Check: 22 + 13/16 = 22.8125 = 364.58 / 16 rounded.
  4. Actual baud = 42 000 000 / 365 = 115 068 baud. Error = 115 068 / 115 200 − 1 = −0.11 %. A UART link tolerates roughly ±3–4 % total, so this is excellent.
Step 3. Turn the byte into bits

'H' in ASCII is 0x48 = binary 0100 1000 (MSB on the left). UART sends the LSB first, so read the binary from the right: 0, 0, 0, 1, 0, 0, 1, 0. Add the start bit (always 0) in front and the stop bit (always 1) at the end:

'H' = 0x48 at 115 200 8N1. Green dots = where the receiver samples (centre of each bit). The falling edge at 0 µs is the only timing reference.
Step 4. What the receiver does
  1. The PC's UART watches the idle-high line. At t = 0 it sees the 1→0 falling edge of the start bit.
  2. It starts its own clock, running at 16 × 115 200 = 1.8432 MHz, and counts 8 ticks to reach the middle of the start bit (t = 4.34 µs). The line is still 0, so it is a real start bit, not a noise spike.
  3. It then samples every 16 ticks: D0 at 13.0 µs, D1 at 21.7 µs, … D7 at 73.8 µs, each in the centre of its bit. (STM32 receivers take three samples, numbers 8, 9 and 10 of the 16, and take the majority.)
  4. At 82.5 µs it samples the stop bit. It must be 1; if it read 0 the receiver would report a framing error.
  5. It assembles the bits LSB first: 0,0,0,1,0,0,1,0 → 0x48 = 'H', puts it in its data register and sets "data ready" (RXNE on an STM32).

Notice why the clocks only need to be roughly equal: the receiver re-starts its count at every start bit, so a small speed difference only has 10 bits to build up. If its clock were 2 % fast, the stop-bit sample would arrive 9.5 × 2 % = 0.19 of a bit early, still well inside the stop bit.

Step 5. The firmware, line by line

05Worked example B — SPI reads a flash chip's ID

Goal: read the 3-byte JEDEC ID from a Winbond W25Q128 flash chip. JEDEC is the standards body; the "Read JEDEC ID" command is the byte 0x9F, and the chip answers with manufacturer 0xEF (Winbond), memory type 0x40 and capacity 0x18 (224 bytes = 16 MB). We use SPI1 on the STM32F407 (clock APB2 = 84 MHz), mode 0, with CS on a GPIO pin.

Step 1. Understand the ring

SPI has no addresses and no acknowledgements. Inside the master and inside the slave sits an 8-bit shift register, and the two are wired into a ring: master output → MOSI wire → slave input, slave output → MISO wire → master input. Each clock cycle pushes one bit out of each register and into the other. After 8 cycles the two bytes have swapped places.

The SPI ring. After 8 clocks the master holds what the slave had and vice versa. "Every read is a write."
Step 2. Plan the transaction

The flash needs the command byte first and then answers during the next three bytes. Because SPI always exchanges, the master must send something during those three bytes too: dummy bytes (0x00 or 0xFF, the flash ignores them).

Byte #Master sends (MOSI)Master receives (MISO)Meaning

20x00 (dummy)0xEFManufacturer ID: Winbond
30x00 (dummy)0x40Memory type
40x00 (dummy)0x18Capacity code: 20x18 = 16 777 216 bytes
## Step 3. Timing with real numbers
1. SPI1 runs from fPCLK2 = 84 MHz. Baud-rate prescaler BR = 010 (÷8) → SCLK = 84 / 8 = 10.5 MHz.
2. One bit = 1 / 10.5 MHz = 95.2 ns. Four bytes = 32 bits = 32 × 95.2 ns = 3.05 µs of clocking.
3. In mode 0 (CPOL = 0: clock idles low; CPHA = 0: sample on the first edge) each side puts a bit on its output, the clock rises (both sample), then the clock falls (both put out the next bit). Each bit therefore gets half a period, 47.6 ns, to travel and settle before it is sampled.
4. The flash datasheet allows up to 104 MHz for most commands, so 10.5 MHz is very safe on a short PCB trace.
## Step 4. The firmware, line by line
[[code SPI1 polling transfer on STM32F407 (mode 0, 10.5 MHz, software CS)]]

SPI1->CR1 |= SPI_CR1_SPE; /* enable: CR1 = 0x0354 */
static uint8_t spi1_xfer(uint8_t out)
{
while (!(SPI1->SR & SPI_SR_TXE)) { } /* room to write? */
*(volatile uint8_t *)&SPI1->DR = out; /* starts 8 clocks */
while (!(SPI1->SR & SPI_SR_RXNE)) { } /* 8 bits came back */
return *(volatile uint8_t *)&SPI1->DR; /* reading clears RXNE */
}
CS_LOW(); /* GPIO: select the flash */
(void)spi1_xfer(0x9F); /* command; answer is junk */
uint8_t mfr = spi1_xfer(0x00); /* 0xEF */
uint8_t type = spi1_xfer(0x00); /* 0x40 */
uint8_t cap = spi1_xfer(0x00); /* 0x18 */
while (SPI1->SR & SPI_SR_BSY) { } /* last bit fully shifted */
CS_HIGH(); /* end of command */

To read the W25Q128 ID I hold CS low, send 0x9F and then three dummy bytes, and collect 0xEF, 0x40, 0x18 from MISO. With SPI1 at 84 MHz divided by 8 that is 10.5 MHz, 32 bits in about 3 µs; I wait for BSY to clear before raising CS.

06Worked example C — I²C reads a temperature

Goal: read the temperature from a TI TMP102 sensor. Its 7-bit address is 0x48 (when its ADD0 pin is tied to GND). The temperature is in its register 0x00, as two bytes. We use I2C1 on the STM32F407 at 400 kHz ("Fast mode"), with APB1 = 42 MHz.

Step 1. The rules of the wire
  1. Both lines idle high (pull-ups). Every chip can only pull low or release (open-drain).
  2. Data on SDA may change only while SCL is low. The receiver reads SDA while SCL is high.
  3. Two exceptions mark the start and end of a transaction: START = SDA falls while SCL is high; STOP = SDA rises while SCL is high. No data bit can ever look like these, because data never changes while SCL is high.
  4. The first byte after START is the address: the 7-bit address shifted left by one, with bit 0 = R/W (0 = write, 1 = read). For 0x48: write byte = 0x48 × 2 + 0 = 0x90, read byte = 0x91.
  5. After every byte comes a 9th clock: the sender releases SDA and the receiver pulls it low = ACK.
Step 2. The transaction, byte by byte

To read a register you first write the register number, then switch to reading without releasing the bus. Switching uses a repeated START (Sr), a START sent without a STOP first.

Step 3. Decode the answer
  1. The two bytes are 0x19 and 0x40 → 16-bit value 0x1940.
  2. The TMP102 puts its 12-bit result in the top 12 bits, so shift right by 4: 0x1940 >> 4 = 0x194 = 404.
  3. Each step is 0.0625 °C: 404 × 0.0625 = 25.25 °C.
Step 4. Timing and pull-ups
  • At 400 kHz one SCL period = 2.5 µs. The transaction has 5 bytes × 9 clocks = 45 clocks = 112.5 µs, plus a few µs for S, Sr and P: about 115 µs to move 2 bytes of data. I²C is slow and has overhead; that is the price of 2 wires.
  • Pull-up value: assume 100 pF of bus capacitance (Cb, from pins and traces). Fast mode allows a rise time tr ≤ 300 ns (30 % → 70 % of VDD). For an RC charge that time is 0.8473 × R × C, so R ≤ 300 ns / (0.8473 × 100 pF) = 3.54 kΩ. The chips must also be able to pull the line below 0.4 V while sinking at most 3 mA, so R ≥ (3.3 − 0.4) / 3 mA = 967 Ω. Choose 2.2 kΩ, safely inside 967 Ω … 3.54 kΩ.
Step 5. The STM32F4 I2C register setup

SAY IT LIKE THISTo read a TMP102 at 0x48 I send START, 0x90 to write the register pointer 0x00, a repeated START, 0x91 to read, then ACK the first byte and NACK the second, and STOP. 0x1940 shifted right by 4 is 404, times 0.0625 is 25.25 °C. 07How the pieces connect: from your C code to the copper

Every transfer on this page goes through the same layers. Knowing the layers tells you where to look when something breaks.

// The layers of a serial transfer
 your code       temp = tmp102_read();              <- application
     |
 driver          i2c_read_regs(0x48, 0x00, buf, 2)  <- C functions you or the vendor wrote
     |              writes/reads peripheral registers, waits on flags,
     |              or lets an interrupt / DMA do the waiting
 peripheral      I2C1->CR1, SR1, DR ...             <- hardware block inside the MCU:
     |              shift register, baud/clock generator, flags
 pins            PB8 = SCL, PB9 = SDA (alternate function AF4, open-drain)
     |
 wires + PHY     PCB traces, pull-ups, RS-485 transceiver, isolator, cable
     |
 the other chip  its own shift register and state machine
Three ways the driver can wait
  1. Polling: the CPU loops on a flag (while(!(SR & TXE));). Simple and fine for a few bytes, but the CPU does nothing else. At 115 200 baud a 100-byte message keeps the CPU busy for 8.7 ms.
  2. Interrupt per byte: the peripheral raises an interrupt when TXE or RXNE sets; the ISR moves one byte. The CPU is free between bytes. Cost: one ISR entry per byte, about 92 000 per second at 921 600 baud, and every one must finish before the next byte arrives (10.85 µs).
  3. DMA: the DMA engine moves every byte between DR and a RAM buffer; the CPU gets one interrupt when the whole buffer is done (or when the line goes idle). This is the answer for high speed or long transfers.
Where the same ideas repeat
  • "Data register empty" is not "done": UART TXE vs TC, SPI TXE vs BSY. The last byte is still in the shift register after the data register empties. This single idea explains the RS-485 truncated-byte bug and the SPI "CS raised too early" bug.
  • Who samples on which edge: UART samples at mid-bit using its own clock, SPI samples on the edge chosen by CPHA, I²C samples while SCL is high. Most "wrong data" bugs are a sampling-point bug.
  • Open-drain = shared wire: ACK, clock stretching, arbitration and the "stuck bus" problem all come from wired-AND.
SAY IT LIKE THISI think of a serial transfer as layers: application, driver, peripheral registers, pins, the physical layer and the other chip. The driver waits by polling, by an interrupt per byte, or by DMA; I pick DMA once the per-byte interrupt rate gets high. And I remember that a data-register-empty flag never means the last bit has left the pin.

// 10.2 — BIT-LEVEL WAVEFORM LAB

Waveform Simulator

Generate the exact line activity for a UART frame, an SPI transfer or an I²C transaction. Step through bit by bit and watch who drives the line and where each side samples. Keys: ←/→ step, Space play.

HOW TO USE THIS LAB · UART
  1. Leave the defaults (0x41, 8N1, 115200, 0 % error) and press Step ▶ 11 times. Watch the dots: each one is where the receiver samples, exactly mid-bit. This shows that a UART needs no clock wire, only the start edge.
  2. Move RX CLOCK ERROR to +3 %. Step to the STOP bit and read the narration: the offset grows by about 3 % of a bit for every bit, but the stop sample is still inside its cell. This is why ±3–4 % is tolerated.
  3. Now set +6 %. The stop-bit sample slides into D7 (which is 0 for 0x41), so the result shows FE · FRAMING ERROR. Change the byte to 0xC1 (D7 = 1) and the same clock error passes unnoticed while the data is wrong. Error tolerance depends on the data.
  4. Select Even parity and 9 data bits: the frame gets longer, and the theoretical tolerance shown in the readout drops (K is larger).
  5. Tick worst-case start-edge detection: every sample moves 1/16 bit late, using part of the budget before any clock error at all.
UART FRAME · TX LINE + RECEIVER SAMPLING
HOW TO USE THIS LAB · SPI
  1. Defaults (mode 0 both sides, 0x9F / 0xA5): Step through the 8 cycles. In each one the master sends one MOSI bit and receives one MISO bit at the same time: after 8 cycles the bytes have swapped. Every read is a write.
  2. Set SLAVE EXPECTS = Mode 1. Step again: the master now samples on the same edge where the slave changes MISO, so it gets the previous bit. The readout shows the received value shifted by one bit, exactly the "half-value ADC" bug.
  3. Set the slave to Mode 3 while the master is Mode 0: both sample on rising edges, so it still works (the flag says so). Devices "supporting modes 0 and 3" only care about the sampling edge.
  4. Switch the master to Mode 1 or 3 (CPHA = 1) and look at the first step: nothing has to be valid when CS falls, because data is only shifted out on the first edge.
  5. Choose LSB first and compare the bit labels: the same byte leaves in the opposite order.
SPI TRANSFER · MASTER + SLAVE SHIFT REGISTERS
HOW TO USE THIS LAB · I²C
  1. Defaults (0x48, write reg + Sr + read): Step through. Note the colours: cyan bits are driven by the master, amber by the slave, grey RC slopes are the pull-up raising a released line. SDA only changes while SCL is low, except at S, Sr and P.
  2. Look at the readout wire byte W / R: 0x90 / 0x91. That is the 7-bit address 0x48 shifted left plus R/W. Now type 0x90 as the address: the flag warns that it looks like an 8-bit form.
  3. Set ADDRESS RESPONSE = NACK: the 9th clock stays high and the master must abort with STOP. This is what a wrong address or an absent device looks like.
  4. Set LAST READ BYTE = Master ACKs (bug): the slave keeps driving SDA, the STOP fails, and you see the start of the famous stuck-bus hang.
  5. Tick slave stretches SCL: after the address ACK the slave holds SCL low (amber) and the master waits. Watch the bus time in the readout grow.

NEVER DO THIS

          
    
            
  • Release RS-485 DE on TXE. The last byte is still in the shift register; wait for TC.
    • 
            
  • Pass a 7-bit address to an API that wants it pre-shifted (STM32 HAL) or vice versa.
    • 
            
  • ACK the last byte of an I²C read. The slave keeps driving SDA and the STOP can fail.
    • 
            
  • Leave an ORE uncleared with RXNEIE on (STM32F4): the ISR re-enters forever.
    • 
            
  • Raise SPI CS on the TX-complete DMA interrupt. Wait for the RX DMA, then BSY = 0.
    • 
            
  • Use TXB0108-style auto-direction push-pull translators on I²C.
    • 
            
  • Put 4.7 kΩ pull-ups on every breakout board, then connect five boards (940 Ω total).
    • 
            
  • Run UART at high baud from an untrimmed RC oscillator across temperature.
    • 
            
  • Stub an RS-485 bus with long drops, or terminate in the middle.
    • 
            
  • Use sizeof(buf) indices without masking in a ring buffer, or let the ISR and main both write the same index.
    • 
            
  • Sample a logic-analyser capture at only 2× the bit rate and trust the decode.
    • 
            
  • Hot-swap an I²C board without a buffer that handles a stuck-low bus (e.g. a PCA9511-class part).
    • 
          

        


        

          
60-SECOND REVISION

          
    
            
  • UART: idle high, start bit 0, data LSB first, optional parity, stop 1. Asynchronous: the falling start edge resynchronises every frame.
    • 
            
  • Receiver oversamples ×16 (or ×8) and majority-votes samples 8/9/10 at mid-bit. Mismatch accumulates across the frame. Keep the total under ~3.75 %.
    • 
            
  • Errors: FE stop bit read 0; PE parity; NF the 3 samples disagree; ORE a new byte arrived before DR was read.
    • 
            
  • Break = line low for longer than a full frame (FE with data 0). LIN uses ≥ 13 bits.
    • 
            
  • RS-485: differential, half duplex, DE on before the first byte and off after TC. 120 Ω at both ends, bias for the idle state. Modbus RTU frames are separated by 3.5 character times of silence.
    • 
            
  • SPI: two shift registers in a ring, full duplex: every read is a write. CPOL = idle level, CPHA = 0 samples the first edge, 1 samples the second. Wrong CPHA shifts the data by one bit.
    • 
            
  • SPI speed is limited by the round trip: SCLK out, slave tV, MISO back and setup must fit in half a period.
    • 
            
  • SPI DMA: start RX before TX, finish on RX complete, wait for BSY to clear, then raise CS. Handle cache maintenance on Cortex-M7.
    • 
            
  • I²C: open drain + pull-ups = wired-AND. START = SDA falls with SCL high, STOP = SDA rises with SCL high. Data changes only while SCL is low.
    • 
            
  • Address byte = (addr7 << 1) | R/W. 9th clock = ACK (receiver pulls low). The master NACKs the last byte it reads.
    • 
            
  • Rp between (VDD − 0.4)/3 mA and tr/(0.8473 · Cb). Long wires mean a slower mode, a lower Rp or a buffer.
    • 
            
  • Stuck SDA: clock SCL up to 9 times until SDA is high, then STOP, then reset the peripheral.
    • 
            
  • Arbitration is bitwise on SDA: whoever sends a 1 but reads a 0 loses. Nothing is corrupted. Clock stretching = a slave holds SCL low.
    • 
            
  • SMBus: 10–100 kHz, 25–35 ms timeout, PEC (CRC-8), ALERT#. PMBus = SMBus plus power commands (LINEAR11). I3C: push-pull 12.5 MHz, dynamic addresses, in-band interrupts.
    •
