// 20.2 — SHARED MEMORY + DOORBELL SIMULATOR

IPC Lab: vring, Caches, Barriers, Mailbox, HW Semaphore

Core A is a Linux host (Cortex-A, write-back L1 D-cache, 64 B lines) acting as the RPMsg driver: it fills buffers, publishes them in the avail ring and kicks a mailbox. Core B is a real-time M-core (Cortex-M7, write-back D-cache, 32 B lines) acting as the device: it takes the doorbell interrupt, consumes buffers and returns them in the used ring. There is no hardware coherency between them, as on i.MX 8M Plus (A53 + M7) or STM32H745 (M7 + M4). Load a preset, step it, then flip one toggle and step it again.

// 20.3 — WORKLOAD PARTITIONING

Partition Planner: Who Runs What?

Target: STM32MP157 running a charger / battery-swap-station controller — 2× Cortex-A7 @ 650 MHz under Linux, 1× Cortex-M4 @ 209 MHz under FreeRTOS. Assign every task to a core. The planner computes utilisation U = Σ C/T per core with the WCET for that core, checks the Liu–Layland bound for rate-monotonic scheduling on the M4, and flags tasks whose timing tolerance is smaller than the worst-case scheduling latency of the core they are on.

TASK SET · C = WCET on that core, T = period, J = jitter/latency tolerance
