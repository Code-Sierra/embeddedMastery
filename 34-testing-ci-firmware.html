// 34 — MOCK / STUB LAB

Test a fan controller on the host

fan_ctrl.c reads a TMP36 sensor through an ADC driver and drives a fan, an alarm and reads a lid switch through a GPIO driver. Pick a test double for each driver, choose which tests run, then run the suite. The JavaScript executes the same logic as the C line by line, so line/branch coverage, the MC/DC table and the mutation results are computed, not scripted. Try: the 4-test "100 % branch" preset, then run mutation analysis; switch GPIO to Stub; switch GPIO to Mock and apply the refactor.

HOW THIS LAB WORKS — READ ONCE
  1. The module. fan_ctrl_step() is called periodically. It reads the TMP36 sensor in millivolts and converts to deci-degrees: t = mV − 500 (so 960 mV → 460 = 46.0 °C). If the ADC fails it turns the fan on (fail-safe). At ≥ 85.0 °C it raises the alarm. Otherwise the fan turns on at ≥ 45.0 °C, stays on while above 40.0 °C if it was already on (hysteresis), and is forced off while the service lid is open.
  2. The doubles. On a PC there is no ADC or GPIO port, so each driver is replaced. The choice decides what the tests can observe: a stub cannot show the fan pin, a fake can, a spy records calls, a mock enforces the exact call sequence.
  3. Running. For each selected test, the lab resets the module (setUp), feeds the test's inputs step by step through the doubles, executes the module logic line by line, and evaluates the test's assertions. Results appear like Unity output.
  4. Coverage. While running the unmutated code, the lab records which lines ran, which way each if went (T/F), and the value of the four conditions on line 39–40 each time it was evaluated. That is exactly what gcov and GCC's condition coverage record.
  5. Mutants. Injecting a mutant changes one operator or statement (shown in violet in the listing). If a test fails, the bug is caught ("killed"). Mutation analysis tries all of them and gives the percentage your test set catches.

COVERAGE (gcov-style, unmutated code)
MC/DC · line 39–40 · (A || (B && C)) && !D
A = t >= T_ON_C10, B = fan_on, C = t > T_OFF_C10, D = gpio_read(PIN_LID_OPEN). Masking pairs treat a short-circuited (not evaluated) condition as don't-care, as GCC 14 -fcondition-coverage and DO-178C masking MC/DC do. Unique-cause pairs require every other condition's value to be identical, which is stricter.
